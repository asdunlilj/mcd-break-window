# 向门店经理提出配合请求 · 微信版

> 用途：以你（学生开发者）的视角，在微信上向校内门店经理提出配合请求
> 原则：**分条短发，不要粘成一大段**；打扰成本前置；给足拒绝空间；不承诺效果
> 生成时间：2026-10-16

---

## 一、A 版 · 推荐（分 4 条发，每条隔几秒）

> **不要合并成一条长消息。** 微信里短消息竖排更好读，而且对方能逐条看、逐条回。

**第 1 条｜打招呼 + 来意**

```
经理您好，我是四川工业科技学院的谢方，上次跟您聊过课间学生排队取餐的事。

那个工具我做出来了，想请您帮个小忙。
```

**第 2 条｜说问题（一句话说清卡在哪）**

```
现在能算"这个课间点什么、大概几分钟能拿到"，但各餐品的实际出餐时间我没有——
官方只公开了薯条7分钟、汉堡60秒这种品类标准，没有到具体每个产品。所以我用的时间是按工序估的，不够准。
```

**第 3 条｜请求（最关键的，单独发）**

```
想请您帮三件事：

1、按您的经验给我一份餐品快慢排序，快/中/慢三档就行，不用精确到分钟，大概占用您5分钟

2、让我到店里看两三次，每次1个半小时左右，挑课间或高峰期。我就站在取餐区记，不进后厨、不碰设备，大概每5分钟才记一单，不打扰同事

3、如果方便，想借一位同事高峰期帮忙记一下出餐时间；另外用这些数据做参赛作品，需要您一句同意
```

**第 4 条｜给台阶 + 澄清**

```
第3条不方便的话，前两条也够我推进，结果我会标成"经验估计"，不会说是实测的。

另外，这是我个人的参赛作品，不是官方工具；也不会采集学生任何个人信息。
```

官方接口没开放这个数据。我不想让您以为能做却做不到。

## 三、B 版 · 极简（对方比较忙时，分 2 条发）

**第 1 条**

```
经理您好，我是四川工业科技学院的谢方，上次跟您聊过课间取餐排队的事。小工具做出来了，卡在"各餐品实际出餐时间我没有"——官方只有品类标准，没有逐个产品的。

想请您帮两件事：
1、按您的经验给我一份餐品快慢排序，快/中/慢三档就行，大概5分钟
2、让我到店里看两三次，每次1个半小时，站取餐区记，不进后厨，每5分钟才记一单
```

**第 2 条**

```
这是我个人的参赛作品，不是官方工具，也不采集学生个人信息。

哪条不方便您直接说，我调整，不影响的。
```

## 四、他可能追问 · 预备回答（只发对应的那一条，不要一次全发）

| 他问 | 就回这一句 |
|---|---|
| 会不会影响营业？ | 不进后厨、不碰设备、不跟同事说话，我站着记。每 5 分钟才记一单，哪个时段特别忙我随时撤。 |
| 为什么要去三次？ | 记录得隔开 5 分钟以上，不然容易把高峰的正常出餐当成异常数据。所以一次能采的样本有限，得分几次。 |
| 数据会不会外传？ | 只用于我个人参赛。不记订单号、姓名、电话，发到作品里的只有脱敏的时间数字。 |
| 能给我们带来什么？ | 老实说现在只是初步模型。它想让课间订单更多流向做得快的餐品，理论上能平一些峰值，但**能不能削峰要靠数据验证，我不承诺效果**。 |
| 要签字吗？ | 微信上您回一句就行。如果您想要正式一点的说明，我写一份给您留档。 |
| 能不能直接导订单数据？ | 能导最好，但订单数据里没有真实出餐时刻，所以还是得到现场记才准。导出数据我用来做回测。 |

## 五、发送要点（只给你看）

1. **分条发，别合并**。这是这版最重要的改动——微信里一大段会被跳过
2. **数字前置**。"5 分钟""1 个半小时""每 5 分钟一单"这三个数字一定要出现在请求前面，这是他判断"要不要答应"的依据
3. **绝不能提"压单时订单会被提前点完成"**。技术文档里可以写，对着他一个字都不能有——那等于当面质疑他的同事
4. **不承诺效果**。说满了，后面数据出来对不上更伤信任
5. **先发文字，别打电话**。他可以自己挑时间看，压力小
6. **当天没回，隔 1–2 天再问一次就够**，不要连追
7. **第一次沟通的目标不是拿到三条，是拿到第 2 条（蹲店许可）**——那才是关键，其余两条有没有都能推进
